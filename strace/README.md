# strace 系统调用追踪

## 写给谁？

本模块假设你完成了 [GDB 模块](../gdb/) 的基础阶段，知道什么是"程序运行时"。不需要预先了解系统调用。

> 如果你从来没想过"程序读写文件时到底发生了什么"，strace 会给你一个全新的视角。

## strace 是什么？

**strace** 拦截并打印一个程序对 Linux 内核发出的**每一个系统调用（syscall）**。

打个比方：

```
┌─────────────────────────────────────────────────┐
│  GDB：你看程序内部的变量和代码执行                │
│        像一个显微镜——放大代码的内部状态           │
├─────────────────────────────────────────────────┤
│  ASan：在内存被破坏时自动报警                     │
│        像一个烟雾探测器——只在出问题时叫           │
├─────────────────────────────────────────────────┤
│  strace：你看程序和操作系统之间的每一句"对话"      │
│        像一个窃听器——监听所有外部交互             │
└─────────────────────────────────────────────────┘
```

### 什么是系统调用？

程序不能直接操作硬件（磁盘、网络、屏幕）。它必须通过"系统调用"请求内核帮忙：

```
你的程序                     Linux 内核
   │                            │
   │  open("file.txt", ...) ──→ │  打开文件
   │         ←── 3 (fd)         │
   │                            │
   │  read(3, buf, 100)  ────→ │  读取内容
   │         ←── 100 (bytes)    │
   │                            │
   │  write(1, "hello", 5) ──→ │  输出到屏幕
   │         ←── 5              │
```

**strace 就是让你看到所有这些 `→` 和 `←` 的工具。**

## 开始之前

### 你需要什么

- Linux 系统（WSL2 / 虚拟机 / Docker 均可——strace 在任何环境都能跑）
- 不需要 root 权限——追踪自己的进程不需要特殊权限

```bash
# 安装（Ubuntu/Debian）
sudo apt install strace

# 验证
strace --version
```

### strace vs 其他追踪工具

| | strace | ltrace | perf |
|------|--------|--------|------|
| 追踪对象 | 系统调用 | 库函数调用 | CPU 性能事件 |
| 输出内容 | `open()`, `read()`, `write()`... | `malloc()`, `printf()`, `strlen()`... | 缓存命中率、分支预测、CPU 周期 |
| 性能开销 | 中（~10-50% 减速） | 高 | 低（~2-5% 减速） |
| 适合场景 | "程序在做什么？为什么卡住了？" | "库函数调用有没有问题？" | "为什么这么慢？哪个函数最耗时？" |

> ⚠️ **perf 状态**：perf 模块因 WSL2 内核版本不匹配暂无法运行（需 `linux-tools-$(uname -r)` 包）。在原生 Linux 或标准虚拟机中 perf 可正常使用。本模块中涉及性能分析的部分会用 strace 的 `-c` 和 `-T` 来覆盖。

### 关键概念速览

| 术语 | 一句话解释 |
|------|-----------|
| **系统调用（syscall）** | 用户程序请求内核服务的唯一方式——打开文件、收发网络、分配内存都需要它 |
| **文件描述符（fd）** | 内核用来标识"打开的文件/网络连接"的数字——`0`=stdin, `1`=stdout, `2`=stderr, `3+`=你打开的文件 |
| **errno** | 系统调用失败时返回的错误码——`ENOENT`=文件不存在，`EACCES`=权限不足，`ECONNREFUSED`=连接被拒 |
| **strace 输出一行** | `函数名(参数...) = 返回值 <耗时>` ——一个完整的"请求-响应"周期 |

## 读 strace 输出的黄金法则

你会在每个实验中反复看到 strace 输出。拿到输出后按这个顺序读：

```
1. 找错误     → 搜索 "= -1"（系统调用失败）
                 看 errno: ENOENT / EACCES / ECONNREFUSED / ...

2. 找耗时     → 搜索 "= 0.0" vs "= 1.5"
                 哪个系统调用花了 >1 秒？那是瓶颈

3. 找模式     → 同一个 open 被调了几百次？文件没缓存！
                 write 只写 1 个字节？缓冲没开！

4. 修 bug     → 改代码 → 重新 strace → 确认问题消失
```

## 遇到问题？

- 每个实验的 README 末尾有"常见错误"小节

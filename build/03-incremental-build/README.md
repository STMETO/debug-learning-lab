# 实验 03：依赖与增量构建 —— make 为什么不总执行 GCC？

> 🎯 **目标**：理解文件时间戳、目标过期、依赖漏写和强制重建。

```bash
make
make
touch hello.c
make
```

Make 对文件目标这样判断：

```text
目标不存在                    → 构建
任意依赖比目标新              → 重新构建
目标比所有依赖都新            → 跳过
```

如果规则漏掉 `hello.c`：

```makefile
hello:
	gcc hello.c -o hello
```

Make 看不到源码和目标的关系，修改源码后可能继续使用旧程序。

## 诊断命令

```bash
make -n    # 只打印计划，不执行
make -B    # 忽略时间戳，强制构建
```

常见问题：

- 改了代码但行为没变：依赖漏写、构建了其他目录、运行了旧二进制；
- 每次都重编译：recipe 没有生成与 target 同名的文件；
- 时间判断异常：系统时间或文件时间戳有问题。

## 🧪 试试看

1. 删除 `hello` 后执行 `make`。
2. 只 `touch hello` 后执行 `make`。
3. 让 target 名称和 recipe 生成的文件名不同，连续执行两次。

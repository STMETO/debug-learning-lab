# GDB 调试入门

## 写给谁？

本模块假设你 **完全没用过 GDB**，甚至可能没写过几行 C。
每个实验都从零开始，手把手带你操作，不跳步、不假设你先懂。

> 如果你卡住了，恭喜——这正是学习调试的常态。调试的秘诀就是：**慢慢来，看清楚每一步**。

## GDB 是什么？

**GDB**（GNU Debugger）是一个让你可以"暂停"运行中的程序、逐行查看代码、检查变量值的工具。

打个比方：
- 你写了一段代码，编译运行，结果不对
- 你加了一堆 `printf` 想找出哪里出错，改了又改
- 有了 GDB，你不需要加 `printf`——你可以让程序**在你怀疑有问题的那一行停下来**，直接看变量是什么值

```
┌─────────────────────────────────────────┐
│  没有 GDB：                              │
│  改代码 → 加 printf → 编译 → 运行 → 猜  │
│  不对 → 再改 → 再加 printf → ...循环     │
├─────────────────────────────────────────┤
│  有 GDB：                                │
│  设断点 → 运行 → 停在那一行 → 看变量值   │
│  单步执行 → 看每行发生了什么 → 找到问题  │
└─────────────────────────────────────────┘
```

## 开始之前

### 你需要什么

- 一台 Linux 机器（WSL2/虚拟机/云服务器/Docker 均可）
- 本项目的 Docker 镜像（推荐，免安装）或手动安装：

```bash
# 手动安装（Ubuntu/Debian）
sudo apt install gdb gcc build-essential
```

### 关键概念速览

在进入实验之前，先了解几个反复出现的词：

| 术语 | 一句话解释 |
|------|-----------|
| **调试符号 (debug symbol)** | 编译时用 `-g` 生成的"代码地图"，GDB 靠它把机器码映射回源代码。没有它，GDB 里只能看到汇编指令和地址 |
| **断点 (breakpoint)** | 程序运行到某一行时自动暂停的标记 |
| **PC / 程序计数器** | CPU 当前正在执行的指令位置。在 GDB 里，它就是"程序现在跑到哪一行了" |
| **栈帧 (stack frame)** | 每次函数调用时创建的一块内存空间，存放参数、局部变量和返回地址。理解"调用栈"的关键 |

### 培养正确的调试心态

> **调试不是找 bug 的过程，而是用实验验证"你以为程序在做的事"和"程序实际在做的事"之间差距的过程。**

每个实验都问问自己：
- 我想验证什么？
- 我期望看到什么？
- GDB 实际显示了什么？如果不一致，**为什么**？
